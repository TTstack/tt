## Native FreeBSD service observations

The authorized dedicated FreeBSD 15.1-RELEASE-p3/amd64 host ran Go 1.26.0 native
race/integration checks and freshly rebuilt Rust database/HTTP tools. Services
used loopback listeners, private temporary data/image/runtime directories,
synthetic authentication and explicit budgets of one CPU, 128 MiB memory and
1024 MiB disk. There were no real guest processes or disks behind the synthetic
stopped VM inventory.

A Go agent started against the Rust-created inventory, then stopped cleanly.
A Rust agent took over that same state, then a Go agent reopened it again. Each
run preserved host identity, VM engine/disk metadata and backup revisions, served
authenticated read APIs, rejected an unavailable QEMU create before allocating a
record, and refused a second process sharing its state lock. Unauthenticated reads
returned 401. The five synthetic records exercised retained cross-platform engine
metadata without launching any engine.

The fixed runtime directory did not exist before testing. The runner created it
for this task, ran the agents as the ordinary test user, then removed only the
empty owned directories. All three service processes and temporary state were
cleaned. A fresh SSH command confirmed reachability and directory cleanup. No
firewall, route, gateway jail, existing service or real guest was changed.

## Gates and remaining scope

Local checks use GOMAXPROCS=2 and package parallelism 1; no local virtualization,
container, cgroup or firewall infrastructure is created. Native FreeBSD full-suite
race/integration checks and CGo-disabled agent/converter builds pass. Minimum-Go
vet/test/build and Linux/FreeBSD cross-build gates pass. The native agent is
confirmed statically linked.

Inspection of earlier GitHub runs found a ZFS-test opt-in ordering bug: generic
integration mode checked for `zfs` before checking whether a dedicated parent had
been supplied. The test now checks the explicit parent first, while still failing
missing prerequisites when ZFS testing is requested. The earlier successful
isolated native ZFS evidence remains in the phase-2 report. The phase-4 GitHub run passed lint, build and ordinary tests. Its Linux race
suite exposed a PID-test assumption: cmdline can become empty before a process is
observably dead. A follow-up test fix preserves the production retention error,
waits for its owned child's confirmed exit, then retries termination. Fifty local
bounded repetitions pass; the new CI result is checked separately. This changes
no process-identity or lifecycle behavior.

Neither authorized Linux host was contacted. Real guest boot, Linux device/kernel
behavior, controller scheduling, CLI workflows and mixed-fleet acceptance remain
later-phase work. This record covers FreeBSD 15.1 only; these service/state results do
not establish working bhyve/Jail guests or SSH readiness.
