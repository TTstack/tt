# CLI, deployment and image parity — 2026-09-30

Reference: TTstack `1ad83a9feed5fac820d74b5e7ef752e50a552740`, version 0.6.0.
The Go phase-6 commit containing this record is the implementation under test.
Reference binaries and template oracle were rebuilt on the authorized dedicated
FreeBSD host, from an archived copy of that revision. The reference checkout was
not modified. SQLite remains pure Go and release/cross builds disable CGo.

## Evidence

- `TestRustCLIOutputAndRequests` compares 24 complete stdout/stderr and HTTP request cases
  captured from the Rust CLI, including status, capabilities, host CRUD/detach,
  environment lifecycle/resize, explicit backup retry headers, image lists and
  recipes, creation and empty tables. The harness uses loopback synthetic data.
- The embedded 32-entry help tree is captured from clap. Parser tests cover
  global flags, repeated image/port values, required backup pairs, numeric bounds
  and subcommand help. Expiry and input tests cover deletion labels, strict guest
  JSON, size limits and SSH public-key file handling.
- `TestDeploymentTemplatesMatchPinnedRust` compares systemd, OpenRC and complete
  remote scripts for both roles, with and without authentication. These four
  cases are generated by the original Rust rendering functions, never by Go.
- Ported Rust deployment tests cover key reuse, conflicting role-key refusal,
  private permissions, mount-guard preservation, disk budgets and preflight
  rejection. Fake-root local deployment exercises binary installation and service
  sequencing. Fake SSH tests verify stdin secrets, SHA-256 upload checks, setup
  failure cleanup and diagnostic redaction. A real `/bin/sh` only syntax-checks
  scripts and exercises the unsupported-OS early refusal with a fake `uname`.
- Image tests cover truncated/error/oversized downloads, atomic replacement,
  checksum mismatch, exact manifest filenames and SHA-256/SHA-512 selection,
  QEMU conversion/publication failure, Docker/Podman selection and aliases, Jail
  staging/completion and Firecracker cleanup. Mount/tool calls are mocked; an
  uncertain unmount retains its staging paths. No local disk mount or VM runs.
- Review found and fixed zero timeouts passed to bounded command execution.
  A harmless shell `printf` exercised both production command wrappers. The
  later [independent review](audit-resolution-2026-09-30.md) corrected the default
  policy for Rust CLI call sites with no timeout; those now use an explicitly
  unbounded runner rather than a zero-duration bounded timer.

## Gates and native service checks

Local Go 1.26.0: clean `gofmt`, `go vet -p 1 ./...`, `go test -p 1 ./...`,
`go build -p 1 ./...`, and CGo-disabled Linux/amd64 and FreeBSD/amd64 builds.
Work was sequential with `GOMAXPROCS=2`; no virtualization infrastructure was
created on the workstation.

FreeBSD 15.1-RELEASE-p3/amd64: the complete `go test -race -p 1 ./...` passed
under Go 1.26.0 with both Rust DB oracles and `TT_TEST_INTEGRATION=1`. Both CLI
binaries then queried each of the four Go/Rust controller-agent combinations:
status, host list/show, environment list, backup inspection, image list and JSON
capabilities produced matching output. The services used five stopped synthetic
VMs; unavailable QEMU creation was refused. Temporary services, databases and
owned `/home/ttstack/run` directories were removed.

`tools/oracle/cli-service-smoke.py PREPARED_NATIVE_TEST_ROOT` retains the service
harness. It expects `bin/{tt,tt-agent,tt-ctl}`, pinned Rust binaries/examples under
`rust-target/debug`, an unused loopback port 9100 and a prepared run directory.
Run only on an authorized native host. Oracle regeneration is described in
[tools/oracle/README.md](../../tools/oracle/README.md).

## Limits

These checks prove CLI/protocol behavior, native service interoperability and
failure contracts. They do not prove actual guest boot, Linux systemd/OpenRC
installation, container workloads or full image construction. Those remain in
phase 7. Neither authorized Linux host was contacted during this phase. FreeBSD
engines in this record were exercised on FreeBSD 15.1 only. No stress testing was performed.
